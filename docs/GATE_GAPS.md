# Gate gaps

Risks that no gate checks yet. Claude proposes entries; only Amal turns one into a gate (`harness/gates.json`, `npm run approve`). Never delete a row: change its status.

Where entries come from (CLAUDE.md rules 9, 10, 11):
- **task sweep**: at the end of every task, a risk sweep across input/paste, layout, editing, export, print, e-paper and backups.
- **bug**: a bug no gate caught (the answer to "which gate should have caught this?" was none).
- **phase review**: the `reviewer` agent's audit at phase end, or a gate review like `demos/gate-review.html`.
- **gate proposal**: after every task, at most 3 proposed gates, ranked by risk. Each states the product risk, how it would be measured, the mutation that must make it fail, its phase and its cost per run. Claude does not edit `harness/gates.json` for these; Amal approves them in batches.

Columns: **Failure** must say what goes wrong on a real issue, not in the abstract. **Measure** says how to get a number, with today's number if one was run. **Status** is open, accepted (Amal agreed it becomes a gate), deferred or rejected. Rendered as a table by `node scripts/gate-gaps.mjs` (writes `demos/gate-gaps.html`).
